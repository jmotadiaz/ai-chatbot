# 06: ADR 0012 — registro in-memory de streams reanudables (sin Redis)

**What to build:** Registrar la decisión de arquitectura de esta spec en
`docs/adr/0012-in-memory-resumable-stream-registry.md`. **En inglés** (los ADR
0001–0011 son legacy en español; los nuevos van en inglés).

**Blocked by:** None (puede ir en paralelo; idealmente tras 01–04 para citar
piezas reales).

**Status:** resolved

- [x] Contexto: turno de chat atado al ciclo de vida del request HTTP;
  persistencia solo en `onFinish`; constraint del operador: nada de Redis.
- [x] Decisión: replay in-memory con el contrato de resume nativo del SDK
  (registry `Map` process-wide + GET de stream + `resume: true` + hook de
  ciclo de vida); supersedes el diseño Redis/`resumable-stream` de la spec
  anterior de `.scratch/chat-resume/`.
- [x] Consecuencias: un solo proceso pm2 es una restricción estructural del
  registry; reinicio a mitad de turno pierde el turno (aceptado); vuelta tras
  TTL exige recargar; el chatbot no gana dependencia de infra nueva.
- [x] Alternativas descartadas: Redis por entorno (+`resumable-stream`),
  adopción del DB tras TTL, replay a medias con offset (el SDK no lo soporta:
  duplica o lanza `UIMessageStreamError`).
- [x] Actualizar `CONTEXT.md` si el glosario gana un término (p. ej. "resumable
  turn").
